FieldSense Frontend Workflow
============================

Purpose
-------
This frontend is the user interface for the Plant Growth Simulation.

The UI allows the user to:
- choose water level: low, medium, or high
- choose sunlight level: low, medium, or high
- start a new simulation
- step the simulation by 1 day
- run the simulation by 7 days
- reset the current simulation
- see plant image changes based on growth stage and health
- see growth, health, stress, and rule feedback


Tech Stack
----------
- React
- TypeScript
- Vite
- Plain CSS

There is no frontend routing library right now.
The app is currently one main simulation page.


Frontend Startup Flow
---------------------
Entry file:
src/main.tsx

What happens:
1. React creates the root.
2. App is rendered inside the root.
3. App loads the dashboard/simulation screen.
4. App automatically starts the first simulation once the page opens.


Main Page
---------
File:
src/App.tsx

This is the main page of the frontend.

It owns the important UI state:
- selected water level
- selected sunlight level
- current simulation id
- current simulation object
- full simulation timeline
- loading/busy state
- error message

Default plant used by the UI:
{
  id: "plant-1",
  name: "Generic Plant",
  idealWater: "medium",
  idealSunlight: "medium",
  growthRate: 5,
  stressThreshold: 40
}

This means the current UI is designed around a plant that grows best when:
- water is medium
- sunlight is medium


Main App Logic
--------------
App.tsx has these main functions.

changeLevel
-----------
Updates local water or sunlight selection.

Important:
Changing the level does not immediately call the backend.
The backend receives the new values when the user clicks:
- Step 1 Day
- Run 7 Days
- New Simulation
- Reset Simulation


createNewSimulation
-------------------
Used by the New Simulation button and first page load.

What it does:
1. Sets loading state.
2. Clears old error message.
3. If there is an old simulation, it calls resetSimulation for the old id.
4. Calls startSimulation with the default plant and selected controls.
5. Receives a new simulation id from the backend.
6. Calls getSimulation to fetch the full stored simulation and timeline.
7. Saves simulation and timeline into React state.


runDays
-------
Used by:
- Step 1 Day button
- Run 7 Days button

What it does:
1. Checks there is a simulation id.
2. Sets loading state.
3. Calls runSimulation with:
   - simulationId
   - number of days
   - current water level
   - current sunlight level
4. Calls getSimulation to fetch the updated timeline.
5. Saves the new simulation and timeline into React state.


resetCurrentSimulation
----------------------
Used by the Reset Simulation button.

What it does:
1. Sets loading state.
2. Clears old error message.
3. If a simulation exists, it resets it in the backend.
4. Starts a fresh simulation with current water/sunlight controls.
5. Fetches the fresh timeline.
6. Updates React state.


Derived UI Values
-----------------
App.tsx calculates a few values from the timeline.

currentState:
The latest item in the simulation timeline.

healthState:
The current plant state:
- healthy
- stressed
- dead

currentDay:
The day shown in the center plant card.

currentHealth:
The health percentage used in the health bar and vitals card.

currentGrowth:
Growth shown in the UI.
The frontend clamps this between 0 and 100 for display.

stage:
Growth stage calculated from current day, growth, and dead state.

plantImage:
The image selected from plant-images based on stage and health state.

statusText:
Human-readable status shown below the plant scene.

appliedRules:
Small tags shown in the Applied Rules Today card.
These explain what the current control setup means for the user.


API Layer
---------
File:
src/api/simulationApi.ts

This file contains all frontend calls to the backend.

Base URL:
VITE_API_BASE_URL from .env

Fallback:
http://localhost:7008/v1

API functions:
- startSimulation
- runSimulation
- getSimulation
- resetSimulation

Backend paths used:
- POST /simulation/start
- POST /simulation/run
- GET /simulation/:id
- POST /simulation/reset

Because the base URL already includes /v1, the final URLs become:
- http://localhost:7008/v1/simulation/start
- http://localhost:7008/v1/simulation/run
- http://localhost:7008/v1/simulation/:id
- http://localhost:7008/v1/simulation/reset


API Response Handling
---------------------
The frontend expects backend responses in this shape:

{
  "status": 200,
  "message": "success",
  "data": {},
  "toastMessage": "Simulation fetched successfully"
}

If the HTTP response is not ok, simulationApi.ts throws an Error using the backend message.
App.tsx catches that error and shows it in the error banner.

Plant Image Logic
-----------------
File:
src/utils/plantAssets.ts

This file imports images from:
plant-images

Images are mapped by:
- growth stage
- health state

Growth stages:
- seed
- sprout
- growing
- mature
- decline

Health states:
- healthy
- stressed
- dead

Main functions:

resolveGrowthStage(state)
-------------------------
Decides which stage the plant should be in.

Rules:
- no state -> seed
- dead state -> decline
- day <= 1 or growth < 4 -> seed
- day <= 6 or growth < 12 -> sprout
- day <= 24 or growth < 32 -> growing
- day <= 40 or growth < 46 -> mature
- otherwise -> decline

getPlantImage(stage, healthState)
---------------------------------
Returns the correct image for the current stage and health.

This is how the UI changes the plant image when the simulation moves forward.


Components
----------
The app is split into small readable components.


HeaderBar
---------
File:
src/components/HeaderBar.tsx

Purpose:
Top navigation and branding.

Shows:
- FieldSense brand
- Dashboard / Simulation / History nav buttons
- New Simulation button
- user avatar

Important action:

ControlsPanel
-------------
File:
src/components/ControlsPanel.tsx

Purpose:
Lets the user control the simulation environment.

Shows:
- Water Level segmented control
- Sunlight Level segmented control
- Step 1 Day button
- Run 7 Days button
- Reset Simulation button

The level options are:
- low
- medium
- high

The selected values are controlled by App.tsx.
This component only displays the controls and sends user actions back to App.tsx.


PlantSimulationCard
-------------------
File:
src/components/PlantSimulationCard.tsx

Purpose:
Main visual plant area.

Shows:
- current day
- plant status badge
- sun/soil scene
- plant image
- status message
- health bar

Status badge labels:
- healthy -> Thriving
- stressed -> Stressed
- dead -> Declined

The scene receives CSS classes based on current water and sunlight:
- sun-low
- sun-medium
- sun-high
- water-low
- water-medium
- water-high

This lets CSS visually adjust the scene depending on selected conditions.

The plant image uses key={imageSrc}.
That makes React remount the image when it changes, so the fade animation runs during stage/health transitions.


GrowthChartCard
---------------
File:
src/components/GrowthChartCard.tsx

Purpose:
Right side insights panel.

Shows:
- Trends chart
- Vitals
- Applied Rules Today

Trend chart:
Uses a small inline SVG.
It draws:
- growth line in green
- health line in amber

Timeline compression:
If the timeline has too many points, it is compressed to a maximum of 8 plotted points.
This keeps the chart readable.

Vitals:
- Health
- Growth
- Stress

Stress calculation:
100 - currentHealth

Applied Rules Today:
Receives rule labels from App.tsx and renders them as small tags.


GrowthStageTimeline
-------------------
File:
src/components/GrowthStageTimeline.tsx

Purpose:
Shows a horizontal lifecycle timeline.

Current note:
This component exists but is not currently rendered inside App.tsx.
It can be reused later if the page needs a separate growth stage strip again.

How To Run Frontend
-------------------
Install dependencies:
npm install

Development:
npm run dev

Build:
npm run build

Preview production build:
npm run preview


Normal User Flow
----------------
1. User opens the frontend.
2. App automatically starts a simulation.
3. Backend creates day 1 state.
4. Frontend fetches the simulation timeline.
5. User changes water/sunlight level.
6. User clicks Step 1 Day or Run 7 Days.
7. Frontend sends current levels to backend.
8. Backend calculates new day states.
9. Frontend fetches the updated timeline.
10. UI updates day, plant image, health, growth, chart, and applied rule tags.


Important Rules For Future Frontend Changes
-------------------------------------------
- Keep water and sunlight as low/medium/high, not percentage sliders.
- Keep API calls inside src/api/simulationApi.ts.
- Keep shared API/data types inside src/types/simulation.ts.
- Keep plant image mapping inside src/utils/plantAssets.ts.
- Keep App.tsx as the main state owner unless the app grows into multiple pages.
- Do not add extra nested project folders inside frontend.
